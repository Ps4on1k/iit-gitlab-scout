ТРЕБОВАНИЯ К КОДУ:

1. АРХИТЕКТУРА:
   - Следуй принципам SOLID, DRY, KISS
   - Раздели код на модули/классы с чёткими обязанностями
   - Используй внедрение зависимостей (DI) там, где это уместно
   - Избегай глобального состояния

2. БЕЗОПАСНОСТЬ:
   - Никаких паролей/токенов в коде — только через переменные окружения
   - Валидируй все внешние входные данные
   - Защита от injection (OS, SQL, XXE)
   - Безопасная работа с файловой системой (без path traversal)

3. ТЕСТИРОВАНИЕ:
   - Напиши unit-тесты для основной логики (используй pytest/unittest/jest)
   - Напиши integration-тест для end-to-end сценария
   - Покрытие критических путей — минимум 80%

4. ОБРАБОТКА ОШИБОК:
   - Конкретные типы исключений, не generic Exception
   - Понятные сообщения об ошибках для пользователя
   - Логирование с уровнями (INFO, WARN, ERROR)
   - Graceful shutdown при критических ошибках

5. ЛОГИРОВАНИЕ:
   - Структурированные логи (JSON)
   - Контекст в каждом логе (request_id, user_id где применимо)
   - Без логирования чувствительных данных

6. ДОКУМЕНТАЦИЯ:
   - Docstring для каждой публичной функции (описание, аргументы, возврат, исключения)
   - README.md: установка, конфигурация, запуск, примеры
   - Файл .env.example со всеми необходимыми переменными
   - Комментарии в коде только для сложной бизнес-логики

7. ТИПИЗАЦИЯ:
   - Полная аннотация типов (Python: mypy совместимо)

8. ПРОИЗВОДИТЕЛЬНОСТЬ:
   - Асинхронные вызовы для I/O операций (aiohttp, httpx.AsyncClient)
   - Пагинация и лимиты для работы с API
   - Кеширование повторяющихся запросов (TTL cache)
   - Потокобезопасность при работе с общими ресурсами

9. УСТОЙЧИВОСТЬ:
