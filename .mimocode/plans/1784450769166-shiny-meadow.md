# План: Оптимизация Dagster — dependencies после languages, исправление зависаний

## Проблемы

1. **`gitlab_languages` дублируется** — есть в `CORE_ASSETS` и `WEEKLY_ASSETS`, запускается дважды
2. **`gitlab_dependency_audit` зависит от `gitlab_dependencies`**, но нет явной зависимости в Dagster
3. **Зависание на сборе языков/зависимостей** — 332 проекта × 1-2 сек rate limit = 5-11 минут только на языки. Dependency audit делает N API вызовов на каждый проект (чтение файлов + проверка версий)
4. **Нет parallel processing** — проекты собираются последовательно

## Решения

### 1. Убрать `gitlab_languages` из `CORE_ASSETS`

Оставить только в `WEEKLY_ASSETS` (вместе с dependency audit).

### 2. Добавить явные зависимости в Dagster

```
gitlab_dependencies → gitlab_dependency_audit
gitlab_languages (теперь только weekly)
```

### 3. Добавить timeouts и max_duration на ассеты

Добавить `max_retry_requests` и timeouts в `gitlab_request` для languages/dependencies.

### 4. Добавить обработку ошибок с continue

В `gitlab_languages` и `gitlab_dependencies` — если проект слишком большой или API отвечает долго, пропускать его с логированием.

## Файлы

| Файл | Изменения |
|------|-----------|
| `dagster/dagster_project/definitions.py` | Убрать `gitlab_languages` из CORE_ASSETS, добавить deps |
| `dagster/dagster_project/assets/gitlab_assets.py` | Добавить timeouts, обработку ошибок в languages/dependencies |
| `dagster/dagster_project/utils/helpers.py` | Добавить timeout параметр в `gitlab_request` |

## Верификация

1. Перезапустить `weekly_audit` — должен выполниться быстрее
2. Проверить что `gitlab_dependency_audit` запускается после `gitlab_dependencies`
3. Проверить что `gitlab_languages` не дублируется
