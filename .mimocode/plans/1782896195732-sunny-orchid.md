# Plan: Fix Deploy Reliability — names, coverage, click filter

## Issue 1: Coverage > 100%
**Root cause:** `pipeline_coverage_rate = completed_pipelines / total_merged_mrs`. One MR can have multiple pipelines → ratio > 100%.

**Fix in** `backend/src/api/v1/contributor-analytics.ts` line 245-247:
- Cap `pipeline_coverage_rate` with `Math.min(100, ...)` 
- Also fix the SQL: use `mrs_with_pipeline` (MRs with at least one pipeline) instead of `completed_pipelines` for the coverage numerator

## Issue 2: Names don't match "Контрибьюторы" tab
**Root cause:** DeployReliability endpoint groups by `displayName` from directory, but the `email` returned might not match the primary email used in contributor profiles if the directory entry was created after profiles.

**Fix in** `backend/src/api/v1/contributor-analytics.ts`:
- After grouping by displayName, also resolve the primary email from `contributor_profiles` table (not just directory) to ensure consistency

## Issue 3: Click filter makes data disappear
**Root cause:** `onContributorClick` adds email to `filters.contributors`. The deploy reliability endpoint then filters MRs by that email. If the email from deploy reliability doesn't match the email in the contributor profiles, no MRs are found → empty data.

**Fix in** `frontend/src/components/contributors/DeployReliabilityDashboard.tsx`:
- When clicking a contributor name, use `record.name` (display_name) instead of `record.email`
- The `onContributorClick` function already resolves through the contributor directory
