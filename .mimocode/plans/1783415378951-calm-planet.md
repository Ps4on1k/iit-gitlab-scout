## 1. Перенести ВСЕ коллекторы в Dagster

### Недостающие коллекторы (5 из 7):

| Backend Collector | Dagster Asset | Что собирает | GitLab API |
|---|---|---|---|
| `collect_branches` | **gitlab_branches** | Ветки проектов | `GET /projects/:id/repository/branches` |
| `collect_stack` | **gitlab_languages** | Языки программирования | `GET /projects/:id/languages` |
| `collect_contributors` | **gitlab_contributors** | Контрибьюторы (из коммитов) | Уже есть в commits, нужен агрегатор |
| `collect_activity` | **gitlab_activity** | Дневная активность | Агрегация из commits + MRs + pipelines |
| `collect_dependencies` | **gitlab_dependencies** | Аудит зависимостей | `GET /projects/:id/repository/tree` + парсинг файлов |

### Файлы для создания/изменения:

**Новые Dagster assets:**
- `dagster/dagster_project/assets/gitlab_assets.py` — добавить 5 новых asset-функций

**Каждый asset должен:**
- Итерировать проекты из БД
- Делать GitLab API запросы (через `gitlab_request_paginated`)
- URL-кодировать пути проектов (`urllib.parse.quote`)
- Batch-вставлять в PostgreSQL (`batch_insert`)
- Использовать token-дешифрование из БД

**`definitions.py`** — зарегистрировать новые assets + обновить schedules

**Schedule** — все assets запускаются в одном job (уже настроено через `__ASSET_JOB`)

### Логика каждого нового asset:

**gitlab_branches:**
```
Для каждого проекта:
  GET /projects/{encoded_path}/repository/branches?per_page=100&page=N
  UPSERT в project_branches (project_id, name, merged, protected, default, last_commit_date, ...)
```

**gitlab_languages:**
```
Для каждого проекта:
  GET /projects/{encoded_path}/languages
  DELETE WHERE project_id = X,然后 INSERT
  Каждый язык = отдельная строка в project_languages
```

**gitlab_contributors:**
```
Для каждого проекта:
  Уже собираем commits — просто агрегируем в contributor_profiles
  SELECT author_email, author_name, COUNT(*), SUM(additions), SUM(deletions) FROM commits
  WHERE project_id = X AND committed_date >= NOW() - INTERVAL '90 days'
  UPSERT в contributor_profiles
```

**gitlab_activity:**
```
Агрегация из commits + merge_requests + pipelines по дням:
  SELECT project_id, date, COUNT(commits), COUNT(mrs), COUNT(pipelines)
  UPSERT в project_activity
```

**gitlab_dependencies:**
```
Для каждого проекта:
  GET /projects/{encoded_path}/repository/tree?recursive=true
  Поиск файлов: package.json, requirements.txt, go.mod, Cargo.toml, etc.
  GET /projects/{encoded_path}/repository/files/{encoded_file_path}/raw
  Парсинг зависимостей + UPSERT в project_dependencies_audit
```

### Rate Limiting (Дагстер):
- Добавить `time.sleep(0.5)` между запросами (2 RPS = 500ms)
- При 429: retry с `Retry-After` или 5 сек
- Лимит 50 страниц на paginated вызов

## 2. Dagster UI за OAuth2 Proxy через Caddy

### Архитектура:
```
Интернет → Caddy (:443)
  /api/* → backend:3000
  /dagster/* → oauth2-proxy:4180 → dagster:3000
  /* → frontend:80
```

### Файлы:
- `docker-compose.yml` — добавить сервис `oauth2-proxy`
- `Caddyfile` — добавить маршрут `/dagster/*`
- `docker-compose.yml` — dagster: убрать `ports:`, оставить только `expose:`

### OAuth2 Proxy конфиг:
```yaml
oauth2-proxy:
  image: quay.io/oauth2-proxy/oauth2-proxy:v7.6
  environment:
    OAUTH2_PROXY_PROVIDER: oidc
    OAUTH2_PROXY_OIDC_ISSUER_URL: ${OIDC_ISSUER_URL}
    OAUTH2_PROXY_CLIENT_ID: ${OIDC_CLIENT_ID}
    OAUTH2_PROXY_CLIENT_SECRET: ${OIDC_CLIENT_SECRET}
    OAUTH2_PROXY_COOKIE_SECRET: ${OAUTH2_PROXY_COOKIE_SECRET}
    OAUTH2_PROXY_HTTP_ADDRESS: "0.0.0.0:4180"
    OAUTH2_PROXY_UPSTREAM: "http://dagster:3000"
    OAUTH2_PROXY_COOKIE_DOMAINS: "${APP_DOMAIN}"
    OAUTH2_PROXY_WHITELIST_DOMAINS: "${APP_DOMAIN}"
    OAUTH2_PROXY_SET_XAUTHREQUEST: "true"
  expose:
    - "4180"
```

### Caddyfile правило:
```
/dagster/* {
    reverse_proxy oauth2-proxy:4180
}
```

## 3. Скрыть ClickHouse из внешней сети

### Проблема:
`docker-compose.yml`: `ports: ["8123:8123", "9000:9000"]` — ClickHouse доступен с хоста.

### Решение:
Заменить `ports:` на `expose:` — ClickHouse доступен только внутри Docker-сети.

### Файл:
- `docker-compose.yml` — секция `clickhouse`:
```yaml
clickhouse:
  image: clickhouse/clickhouse-server:24.3-alpine
  expose:
    - "8123"
    - "9000"
```

## 4. Active Directory / SSO (OIDC)

### Архитектура:
```
Гибридный режим: логин/пароль + OIDC SSO
  - Локальные аккаунты: для админов, fallback
  - SSO аккаунты: для сотрудников через Azure AD / Keycloak
```

### 4.1 Миграция БД:
**Файл:** `backend/migrations/046_add_sso_columns.cjs`
```sql
ALTER TABLE app_users ALTER COLUMN password_hash DROP NOT NULL;
ALTER TABLE app_users ADD COLUMN external_provider text;
ALTER TABLE app_users ADD COLUMN external_id text;
ALTER TABLE app_users ADD COLUMN display_name text;
ALTER TABLE app_users ADD COLUMN email text;
ALTER TABLE app_users ADD COLUMN last_sso_login_at timestamptz;
CREATE UNIQUE INDEX idx_app_users_external_id ON app_users (external_id) WHERE external_id IS NOT NULL;
```

### 4.2 Config:
**Файл:** `backend/src/config.ts` — добавить:
- `SSO_PROVIDER`: `"local"` | `"oidc"`
- `OIDC_ISSUER_URL`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, `OIDC_CALLBACK_URL`
- `SSO_DEFAULT_ROLE`: `"user"` (по умолчанию)
- `OAUTH2_PROXY_COOKIE_SECRET` (для Dagster proxy)

### 4.3 Backend endpoints:
**Файл:** `backend/src/api/v1/auth.ts`

**POST /api/v1/auth/sso/authorize:**
- Генерирует state token (CSRF protection)
- Редиректит на `{OIDC_ISSUER_URL}/authorize?client_id=...&redirect_uri=...&state=...&scope=openid email profile`

**GET /api/v1/auth/sso/callback:**
- Получает code от IdP
- Обменивает на tokens (introspection endpoint)
- Извлекает `sub`, `email`, `name` из ID token
- UPSERT в `app_users` (external_id, external_provider, display_name, email)
- Подписывает локальный JWT
- Редиректит на фронтенд с токеном в URL

### 4.4 Auth guard:
- Login route: если `external_provider != null && external_provider != 'local'` → отклонить пароль, вернуть `{ error: "Используйте SSO для входа" }`
- Password change: если SSO пользователь → 403
- Seed: если `SSO_PROVIDER != 'local'` → не создавать дефолтные аккаунты

### 4.5 Frontend:
- Login page: кнопка "Войти через SSO" → `GET /api/v1/auth/sso/authorize`
- Callback: страница `/auth/callback?token=...` — сохраняет токен, редиректит на dashboard
- UserManagement: показывать `external_provider`, скрыть смену пароля для SSO
- Settings: показывать "Вход через: Azure AD" / "Локальный"
